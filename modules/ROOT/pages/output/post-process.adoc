== Description

The image:CAM_Post.svg[width=24] xref:output/post-process.adoc[CAM Post] command (tooltip: _Post Processes the selected Job_) exports the selected image:CAM_Job.svg[width=16] xref:job/job.adoc[CAM Job] to a G-code file. The toolbar button is part of the *Post process Operations* drop-down group in the *Project Setup* toolbar, together with image:CAM_PostSelected.svg[width=16] xref:output/post-process-selected.adoc[Post Process Selected].

*Each CNC controller speaks a specific G-code dialect, requiring a dialect-correct Post-Processor to translate the final output from the agnostic internal FreeCAD G-code dialect* (see xref:reference/scripting.adoc#the-freecad-internal-g-code-format[FreeCAD's internal G-code format]).

=== Typical functions of the Post-Processor include

* Using a correct Job output G-code file extension.
* Selecting the G-code commands. CNC controllers typically support a subset of available G-code commands. The super-set of G-code commands contains powerful and specialized commands that otherwise must be processed using multiple simpler commands. Post-Processors are written to select the best G-code for an Operation, available on the target.
* Formatting the G-code syntax by reordering the Feed, X, Y, Z, A, and B inputs, and the precision.
* Inserting a preamble to set units, units format, work plane, coordinate system, etc.
* Inserting a postamble to park the machine, stop it, process any arguments.
* Inserting tool changes, or suppressing them between subsequent Operations using the same Tool Controller.
* Formatting the feed and speed rate information to revolutions per minute, or per second.
* Formatting function call naming and calling.

Typical CNC machine controller targets include CNC mills, CNC lathes, 3D printers, drag-knife cutters, laser cutters, engravers and plasma torch cutters.

If you want to write your own Post-Processor, have a look at the xref:output/postprocessor-customization.adoc[CAM Postprocessor Customization] page. Several provided Post-Processors generate suitable code for many CNC controllers, or can be used as templates for modification.

=== Two flows: machine-based and legacy

If the Job's *Machine* property is set ([.since]#introduced in 26.3#), the machine definition decides the Post-Processor (its _postprocessor_ entry) and the output options, and the Job's *PostProcessor* property is ignored. Machine-based Post-Processors cannot be selected in the Job's Processor combo; legacy ones cannot be assigned to a Machine. See xref:output/machine.adoc[CAM Machine].

For legacy argument-based Post-Processors, the settings are module-level flags of the script, usually changed through the Job's *Arguments* field (e.g. `--no-header --line-numbers --precision 4`; hover the Arguments field for the list). For machine-based Post-Processors the same settings are *Output options* of the Machine (`.fcm`) edited in the xref:output/machine.adoc[Machine Editor] or overridden per export on the Options tab of the Post Processing dialog.

== Usage

. Select the image:CAM_Job.svg[width=16] xref:job/job.adoc[CAM Job] (or any of its Operations) in the https://wiki.freecad.org/Tree_View[Tree View].
. There are several ways to invoke the command:
* Press the image:CAM_Post.svg[width=16] xref:output/post-process.adoc[Post Process] button in the *Post process Operations* toolbar drop-down.
* Select the menu:CAM[Post Process] option from the menu.
* Select *Post Process* from the context menu of the Job.
* Use the keyboard shortcut: kbd:[P] then kbd:[P].
. If the Job has no Machine (legacy flow): the G-code is generated with the Job's legacy Post-Processor (or the default from preferences, or a *Post Processor* selection dialog if none is set). Most legacy posts show the G-code in an editor with line numbers ([.since]#line numbers introduced in 26.3#) where you may edit or cancel; the file is then written according to the File save policy (see below).
. If the Job has a Machine ([.since]#introduced in 26.3#, machine-based flow): the *Post Processing* dialog opens (see below); press btn:[Generate Output], review the files on the Output tab and press btn:[Save to Disk].

If neither the Job nor the preferences define a Post-Processor, a *Post Processor* dialog lists the enabled ones; double-click to choose.

== Post Processing dialog

[.since]#introduced in 26.3#

When the Job has a Machine, post-processing opens the dialog titled _Post Processing - Job: <name>_. Its tabs are:

* *Overview*:
** *Machine*: the `.fcm` machine to use; defaults to the Job's Machine, _(none)_ falls back to the legacy Post-Processor.
** *Fixtures*: check the work coordinate systems to include.
** *Job Details*: Author and Comment written into the G-code header.
** *Options*: *Generate HTML sanity report*.
** *Post Processor Parameters*: runtime properties declared by the machine's Post-Processor, e.g. LinuxCNC path blending.
* *Operations*: check the Operations to export (inactive Operations are not listed); btn:[Select All], btn:[Select None], btn:[Workplan] (shows the ordered list of postable items with estimated times).
* *Options*: the machine's output options (units, header, comments, formatting, precision, duplicates, processing) and the non-runtime Post-Processor properties; changes apply to this export only.
* *Output*: *Output folder* with btn:[Browse…], *Filename template* (%j job name, %d document, %T tool, %W fixture, %O operation; btn:[Apply] renames the generated files), the list of generated files (rename via the context menu) and an editable G-code view. btn:[Save to Disk] writes every file and closes the dialog.
* *Warnings*: result of the xref:job/sanity-check.adoc[sanity checks] (Severity, Note); the tab label shows the count.

== Output file name

In the legacy flow the file name comes from the Job's *PostProcessorOutputFile*, otherwise from the preference *Output File → Default path*, otherwise the document name in the document's folder. Whether a file dialog appears depends on the File save policy preference. Placeholders: %D document directory, %d document name, %M macro directory, %j Job label; in the file name, when output is split: %T tool number, %t Tool Controller label, %W fixture, %O operation label, %S sequence number. Without an extension `.nc` is used; machine-based Post-Processors apply their own extension (e.g. `.ngc` for LinuxCNC).

menu:Edit[Preferences > CAM > Job preferences > Post processor > File save policy] offers: *Open file dialog* (always ask), *Open file dialog on conflict*, *Overwrite existing file*, *Append Unique ID on conflict* (adds -1 to the name). The policy applies to the legacy flow; the Post Processing dialog always writes the files listed on its Output tab.

== Preferences

menu:Edit[Preferences > CAM > Job preferences > Post processor]: enable or disable installed Post-Processors, choose the default Post-Processor and default arguments, the default output path and the file save policy.

== Header

Machine-based output starts with a comment header that can include exporter, machine name, Post-Processor, project file, document name, description, author, date, units, tool list and fixture list; each item can be switched off in the Machine's Header Options.

== Included Post-Processors

Included Post-Processors live in `<FreeCAD>/Mod/CAM/Path/Post/scripts`.

* Machine-based ([.since]#introduced in 26.3#, used through a xref:output/machine.adoc[Machine]): centroid, generic, generic_plasma, http://linuxcnc.org/docs/html/gcode/g-code.html#gcode:g17-g19.1[linuxcnc], mach3_mach4, marlin, opensbp, smoothie.
* Class-based, selectable as legacy posts in the Job: grbl (with support for bCNC header blocks using the argument `--bcnc`), masso_g3, svg, test.
* Legacy argument-based scripts ([.since]#renamed with the `_legacy` suffix in 26.3#): centroid_legacy, dxf, dynapath_legacy, dynapath_4060_legacy, estlcam_legacy, fablin_legacy, fangling_legacy, fanuc_legacy, grbl_legacy, heidenhain_legacy, jtech_legacy (laser), KineticNCBeamicon2_legacy, linuxcnc_legacy, mach3_mach4_legacy, marlin_legacy, nccad_legacy, opensbp_legacy, philips_legacy, rml_legacy, rrf_legacy, snapmaker_legacy, uccnc_legacy, wedm_legacy.
* Pre-processors for importing G-code: gcode_pre, opensbp_pre, slic3r_pre.

snapmaker, masso_g3 and svg were added in [.since]#1.1#; fanuc, dynapath_4060, generic, generic_plasma and the machine-based versions in [.since]#26.3#.

Additional Post-Processors are found in the macro directory, in the CAM file path preference, and in any installed add-on whose `package.xml` declares a Postprocessor content item (e.g. the FreeCAD/Machines add-on).

To post-process only some Operations of a Job, use xref:output/post-process-selected.adoc[CAM PostSelected] ([.since]#introduced in 26.3#).

== Job properties

See xref:job/job.adoc#_properties[CAM Job]: Output File, Post Processor, Arguments, Machine ([.since]#26.3#), Fixtures, Order Output By, Split Output and Post Processor Property Overrides ([.since]#26.3#). After a successful export the hidden *LastPostProcessDate* and *LastPostProcessOutput* properties are updated and used by xref:job/sanity-check.adoc[CAM Sanity].

== Scripting

[source,python]
----
from Path.Post.Processor import PostProcessorFactory
post = PostProcessorFactory.get_post_processor(job, 'linuxcnc')
sections = post.export2()   # machine-based; use post.export() for legacy posts
for name, gcode in sections:
    print(name, len(gcode))
----

== Limitations

* Do *not* use the menu:File[Export] menu option for export to G-code, it will produce damaged G-code!
