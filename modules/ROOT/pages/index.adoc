== Introduction

The image:Workbench_CAM.svg[width=24] xref:index.adoc[CAM Workbench] is used to produce machine instructions for https://en.wikipedia.org/wiki/CNC_router[CNC machines] from a FreeCAD 3D model. These produce real-world 3D objects on CNC machines such as mills, routers, lasercutters, or similar. Typically, instructions are a https://en.wikipedia.org/wiki/G-code[G-code] dialect.

image::Pathwb.png[width=600]

[.caption]
Screenshot of the former Path Workbench interface; toolbars and command names have changed since the rename to CAM.

The FreeCAD CAM Workbench workflow creates these machine instructions as follows:

* A 3D model is the base object, typically created using one or more of the image:Workbench_PartDesign.svg[width=24] https://wiki.freecad.org/PartDesign_Workbench[Part Design], image:Workbench_Part.svg[width=24] https://wiki.freecad.org/Part_Workbench[Part] or image:Workbench_Draft.svg[width=24] https://wiki.freecad.org/Draft_Workbench[Draft] Workbenches.
* A xref:job/job.adoc[Job] is created. It holds the Model, the Stock, the Tool Controllers that reference Tool Bits from a xref:tools/toolbit-library.adoc[Tool Library], the Operations, and the Post-Processor selection.
* Optionally a xref:output/machine.adoc[Machine] definition is selected for the Job (Machine Library, [.since]#introduced in 26.3#) so that post-processing and rotary kinematics use the machine's axis configuration.
* Toolpaths are created using Operations such as xref:operations/profile.adoc[Profile] and xref:operations/pocket.adoc[Pocket Shape]. These CAM objects use the internal FreeCAD G-code dialect, independent of the CNC machine.
* xref:job/sanity-check.adoc[Sanity Check] is run before post-processing to report missing Tool Controller speeds, depths, or output settings.
* The Job is exported to G-code matching your machine. This step is called _post processing_; there are different Post-Processors available.

== General concepts

The CAM Workbench generates G-code defining the Toolpaths required to mill the model on the target machine in xref:reference/scripting.adoc#the-freecad-internal-gcode-format[the FreeCAD internal G-code dialect], which is later translated to the appropriate dialect for the target CNC controller by the selected Post-Processor.

The G-code is generated from directives and Operations contained in a CAM Job. The Job Workflow lists these in the order they will be executed. The list is populated by adding Operations, Path Dressups, Supplemental Commands, and Path Modifications from the CAM menu, or GUI buttons.

The CAM Workbench provides a xref:tools/library-manager.adoc[Toolbit Library Manager] and a xref:tools/add-toolbit.adoc[Toolbit selector], G-code inspection, and two simulators. It links the Post-Processor and allows importing and exporting Job Templates.

The CAM Workbench has external dependencies including:

. The FreeCAD 3D model units are defined in menu:Edit[Preferences > General > Default unit system]. The Post-Processor and Machine configuration define the final G-code units.
. The default Job Template, geometry tolerance, curve accuracy, default Post-Processor, output path and file-save policy, and default Stock are defined on the menu:Edit[Preferences > CAM > Job Preferences] page.
. Asset storage location and the Machine Library (Add, Edit, Delete machine definitions, [.since]#introduced in 26.3#) are managed on the menu:Edit[Preferences > CAM > Assets] page.
. Colors are defined in the menu:Edit[Preferences > CAM > GUI] tab.
. Holding tag parameters are defined in the menu:Edit[Preferences > CAM > Dressups] tab.
. Warning suppression and OpenCamLib activation are on the menu:Edit[Preferences > CAM > Advanced] page; see xref:reference/experimental.adoc[CAM experimental].
. That the base 3D model quality supports the CAM Workbench requirements, passes https://wiki.freecad.org/Part_CheckGeometry[Check Geometry].

The preference pages under CAM appear in this order: Assets, Job Preferences, Dressups, GUI, Advanced.

== Limitations

Some current limitations of which you should be aware are:

* Most Operations are not true 3D but only 2.5D capable. This means that they take a fixed 2D shape and can cut it down to a given depth. However, several Operations produce true 3D Toolpaths: image:CAM_3DPocket.svg[width=24] xref:operations/pocket-3d.adoc[3D Pocket], image:CAM_3DSurface.svg[width=24] xref:operations/surface.adoc[3D Surface], image:CAM_Waterline.svg[width=24] xref:operations/waterline.adoc[Waterline] and, with experimental features enabled, image:CAM_RotarySurface.svg[width=24] xref:operations/rotary-surface.adoc[Rotary Surface] [.since]#introduced in 26.3#.
* Most Operations target a 3-axis (XYZ) CNC mill or router. Indexed 3+2 positioning is derived from the selected Machine definition ([.since]#introduced in 26.3#), and continuous 4-axis surfacing is provided by the experimental xref:operations/rotary-surface.adoc[Rotary Surface] Operation. Lathe Operations are available through the external https://github.com/dubstar-04/TurningAddon[TurningAddon] add-on, which has no page in this documentation (see xref:reference/faq.adoc[CAM FAQ]).
* Most Operations generate Toolpaths as if the Tool Bit were a plain end mill, regardless of the Tool Shape assigned to the Tool Controller. [.since]#introduced in 26.3#: linking moves, xref:operations/engrave.adoc[Engrave], xref:operations/surface.adoc[3D Surface] and the drilling-family Operations now account for the Tool Shape.
* The Operations within the CAM Workbench are not aware of clamping mechanisms in use to secure the model to your machine. Consequently, please review and simulate the Toolpaths you generate prior to sending the code to your machine. If necessary, model your clamping mechanisms in FreeCAD in order to better inspect the Toolpaths generated. Look for possible collisions with clamps or other obstacles along the Toolpaths.

== Units

Unit handling in CAM can be confusing. There are several points to understand:

. FreeCAD base units for length and time are 'mm' and 's' respectively. Velocity is thus 'mm/s'. This is what FreeCAD stores internally regardless of anything else.
. The default unit schema uses the default units. If you're using the default schema and you enter a feed rate without a unit string, it will get entered as 'mm/s'.
. Most CNC machines expect feed rate in the form of either 'mm/min' or 'in/min'. Most Post-Processors will automatically convert the unit when generating G-code.

Schemas:

. Changing schema in preferences changes the default unit string for the input fields. If you design in metric, use the "Metric small parts & CNC (mm, mm/min)" schema. If you design in US units, "Imperial decimal (in, lb)", "US customary (in, lb)" or "Building US (ft-in, sqft, cft)" will work.
. Changing your preferred unit schema will have no effect on output but will help avoid input errors.
. [.since]#introduced in 26.3#: The Job creation dialog includes a unit schema selector, and each Tool Bit stores its own _Units_ (Metric or Imperial).

Output:

. Generating the correct unit in output is the responsibility of the Post-Processor and is done only at that time.
. Machine output unit is completely unrelated to your selected unit schema.
. Post-Processors produce either metric (G21) output, imperial (G20) output, or are configurable. Configurable Post-Processors default to metric (G21).
. For machine-based Post-Processors ([.since]#introduced in 26.3#) the output unit is part of the xref:output/machine.adoc[Machine] definition. For legacy Post-Processors (`*_legacy_post`), pass the argument in the Job's output configuration (for example `--inches` for linuxcnc_legacy). Either can be stored in a Job Template and set as your default template to make it automatic for all future Jobs.

Inspection:

. xref:inspect/inspect.adoc[Inspect Toolpath] shows the internal G-code, so feed rates appear in mm/s because the Toolpath has not been post-processed.

== Commands

Some commands are hidden until OpenCamLib support or experimental features are enabled in the CAM Advanced preferences. See xref:reference/experimental.adoc[CAM experimental].

=== Project Commands

* image:CAM_Job.svg[width=32] xref:job/job.adoc[New Job]: Creates a new CNC Job.

* image:CAM_Sanity.svg[width=32] xref:job/sanity-check.adoc[Sanity Check]: Checks the Job for common errors and produces an HTML report.

* xref:job/quick-validate.adoc[Quick Validate]: Runs a fast validation of the Job without generating the full Sanity report. Not present in toolbars or menus; available through the shortcut kbd:[P] then kbd:[V].

* image:CAM_Post.svg[width=32] xref:output/post-process.adoc[Post Process]: Post-processes the selected Job to G-code using the chosen Post-Processor and Machine, with a preview of the output. [.since]#introduced in 26.3#: redesigned dialog with Overview, Operations, Workplan tabs and an output filename template.

* image:CAM_PostSelected.svg[width=32] xref:output/post-process-selected.adoc[Post Process Selected]: Post-processes only the selected Operations of a Job, including Operations inside a Dressup. [.since]#introduced in 26.3#

* image:CAM_ExportTemplate.svg[width=32] xref:job/export-template.adoc[Export Template]: Exports the current Job as a template.

=== Tool Commands

* image:CAM_SimulatorGL.svg[width=32] xref:inspect/simulator.adoc[CAM Simulator]: Simulates the G-code on the Stock in a dedicated simulator window inside the main window. [.since]#introduced in 1.0#; integrated as a document window in [.since]#26.3 and later#. The simulators share one toolbar button group; set the `DefaultSimulatorLegacy` parameter to make the legacy simulator the default.

* image:CAM_Simulator.svg[width=32] xref:inspect/simulator-legacy.adoc[Legacy CAM Simulator]: Shows the milling operation like it's done on the machine.

* image:CAM_Camotics.svg[width=32] xref:inspect/camotics.adoc[CAMotics]: Simulates the Job with the external CAMotics simulator; requires the _Enable OCL dependent features_ preference and CAMotics 1.2.2 or newer (command-line `camotics` and its Python module). Shortcut kbd:[P] kbd:[C].

* image:CAM_Inspect.svg[width=32] xref:inspect/inspect.adoc[Inspect Toolpath]: Shows the internal G-code of an Operation for checking.

* image:CAM_SelectLoop.svg[width=32] xref:inspect/select-loop.adoc[Finish Selecting Loop]: Completes the selection of edges or faces that form a loop from one or two selected edges or a face; modifier keys select inner edges (kbd:[Ctrl]), outer edges (kbd:[Ctrl+Alt]), faces at the same height (kbd:[Shift]) or all edges (kbd:[Alt]). Shortcut kbd:[P] kbd:[L].

* image:CAM_OpActive.svg[width=32] xref:inspect/op-active-toggle.adoc[Toggle Operation]: Toggles the Active state of the selected Operations, or of every Operation when a Job or its Operations group is selected ([.since]#introduced in 26.3#). Shortcut kbd:[P] kbd:[X].

* image:CAM_ToolTable.svg[width=32] xref:tools/library-manager.adoc[Toolbit Library Manager]: Opens the editor for Tool Libraries and Tool Bits (CAM menu only).

* image:CAM_ToolTable.svg[width=32] xref:tools/add-toolbit.adoc[Add Toolbit…]: Opens the Toolbit selector dock to add a Tool Controller to the Job. Shortcut kbd:[P] kbd:[T].

* image:CAM_ToolBit.svg[width=32] Save Toolbit / Save Toolbit As: available in the context menu of a Tool Bit in the Job tree; writes the Tool Bit back to its library file. New Toolbit and Load Tool commands exist but are reachable only through the Toolbit Library Manager.

[.since]#introduced in 26.3#: The xref:tools/tool-controller.adoc[Tool Controller] editor includes a xref:tools/feeds-speeds.adoc[Feeds and Speeds Wizard] that proposes feed and spindle values from the Tool Bit and a selected material, and Tool Bits embedded in a Job can be updated to their current library version.

=== Basic Operations

* image:CAM_Profile.svg[width=32] xref:operations/profile.adoc[Profile]: Creates a profile Toolpath from the entire model, or from one or more selected faces or edges.

* image:CAM_Pocket.svg[width=32] xref:operations/pocket.adoc[Pocket Shape]: Creates a pocket Toolpath from selected faces or, in [.since]#26.3 and later#, horizontal edges.

* image:CAM_Face.svg[width=32] xref:operations/mill-facing.adoc[Mill Facing]: Machines the top surface of the Stock or selected faces with zigzag, directional, bidirectional or spiral patterns. [.since]#introduced in 26.3# (replaces the Face operation).

* image:CAM_Helix.svg[width=32] xref:operations/helix.adoc[Helix]: Creates a helical drilling Toolpath from circular holes of the Model.

* image:CAM_Adaptive.svg[width=32] xref:operations/adaptive.adoc[Adaptive]: Creates an adaptive clearing and profiling Operation.

* image:CAM_Slot.svg[width=32] xref:operations/slot.adoc[Slot]: Creates a single horizontal slot between two points taken from selected geometry or custom points.

==== Drilling Operations

* image:CAM_Drilling.svg[width=32] xref:operations/drilling.adoc[Drilling]: Creates a drilling-cycle Toolpath from circular holes; the _Strategy_ property selects Drilling or Tapping (G84/G74) [.since]#introduced in 26.3#.

* image:CAM_ThreadMilling.svg[width=32] xref:operations/thread-milling.adoc[Thread Milling]: Creates a Thread Milling Operation from features of a base object.

==== Engraving Operations

* image:CAM_Engrave.svg[width=32] xref:operations/engrave.adoc[Engrave]: Creates an engraving Toolpath along the edges of a Draft ShapeString or other selected edges.

* image:CAM_Deburr.svg[width=32] xref:operations/deburr.adoc[Deburr]: Creates a chamfering Toolpath along selected edges or around faces.

* image:CAM_Vcarve.svg[width=32] xref:operations/vcarve.adoc[Vcarve]: Creates a medial-line engraving Toolpath with a V-bit Tool Bit.

=== 3D Operations

* image:CAM_3DPocket.svg[width=32] xref:operations/pocket-3d.adoc[3D Pocket]: Creates a Toolpath for a 3D pocket.

* image:CAM_3DSurface.svg[width=32] xref:operations/surface.adoc[3D Surface]: Creates a 3D surfacing Toolpath using OpenCamLib. Requires _Enable OCL dependent features_.

* image:CAM_Waterline.svg[width=32] xref:operations/waterline.adoc[Waterline]: Creates waterline Toolpaths; [.since]#26.3 and later# adds the OCL Adaptive algorithm. Requires _Enable OCL dependent features_.

* Planar Surface: Creates a Planar Surface Operation from a model. Requires _Enable OCL dependent features_ and xref:reference/experimental.adoc[experimental features]. [.since]#introduced in 26.3#

* image:CAM_RotarySurface.svg[width=32] xref:operations/rotary-surface.adoc[Rotary Surface]: Continuous 4-axis surfacing of a Model mounted on a single rotary axis. Requires _Enable OCL dependent features_ and xref:reference/experimental.adoc[experimental features]. [.since]#introduced in 26.3#

=== Path Dressup

All Dressup commands share the image:CAM_Dressup.svg[width=24] Dressup icon.

* image:CAM_Dressup.svg[width=32] xref:dressups/array.adoc[Array]: Creates a linear, polar or points-based array of a selected Operation's Toolpath as a Dressup; preferred over the Array Path Modification. [.since]#introduced in 1.1#

* image:CAM_Dressup.svg[width=32] xref:dressups/axis-map.adoc[Axis Map]: Remaps one axis of a Toolpath to another.

* image:CAM_Dressup.svg[width=32] xref:dressups/path-boundary.adoc[Boundary]: Adds a boundary Dressup to a selected Toolpath.

* image:CAM_Dressup.svg[width=32] xref:dressups/dogbone.adoc[Dogbone]: Adds a dogbone Dressup to a selected Toolpath.

* image:CAM_Dressup.svg[width=32] xref:dressups/drag-knife.adoc[Drag Knife]: Adds a dragknife Dressup to a selected Toolpath.

* image:CAM_Dressup.svg[width=32] xref:dressups/lead-in-out.adoc[Lead In/Out]: Adds a lead-in and/or lead-out to a selected Toolpath. [.since]#26.3 and later# adds the _LineZFollow_ style.

* image:CAM_Dressup.svg[width=32] xref:dressups/mirror.adoc[Mirror]: Mirrors the Toolpath of a selected Operation across a chosen axis or plane. [.since]#introduced in 26.3#

* image:CAM_Dressup.svg[width=32] xref:dressups/ramp-entry.adoc[Ramp Entry]: Adds a ramp entry Dressup to a selected Toolpath. [.since]#26.3 and later#: can be applied on top of Lead In/Out.

* image:CAM_Dressup.svg[width=32] xref:dressups/tag.adoc[Tag]: Adds a holding tag Dressup to a selected Toolpath. [.since]#26.3 and later#: places tags automatically on several closed Toolpaths.

* image:CAM_Dressup.svg[width=32] xref:dressups/zcorrect.adoc[Z Depth Correction]: Corrects the Z depth using a Probe Map. [.since]#26.3 and later#: points outside the probed area produce a warning instead of an error.

=== Supplemental Commands

* image:CAM_Comment.svg[width=32] xref:operations/comment.adoc[Comment]: Adds a comment to the CNC program.

* image:CAM_Stop.svg[width=32] xref:operations/stop.adoc[Stop]: Inserts a full stop of the machine.

* image:CAM_Custom.svg[width=32] xref:operations/custom.adoc[Custom]: Inserts a custom G-code snippet; [.since]#26.3 and later# supports https://wiki.freecad.org/Expressions[expressions] enclosed in @ characters.

* image:CAM_Probe.svg[width=32] xref:operations/probe.adoc[Probe]: Creates a probing grid from a Job's Stock.

* xref:operations/path-from-shape-tc.adoc[Path from Shape]: Creates a Toolpath object from a selected Part shape using a Tool Controller. [.since]#introduced in 1.1#, xref:reference/experimental.adoc[_Experimental_]. Replaces the earlier From Shape command.

=== Path Modification

* image:CAM_OpCopy.svg[width=32] xref:modify/copy.adoc[Copy Operation]: Copies the selected Operations, including their Dressups, into the Job ([.since]#26.3 and later#: multiple selection and recursive copy).

* image:CAM_Array.svg[width=32] xref:modify/array.adoc[Array]: Creates an array from selected Toolpaths; [.since]#26.3 and later# adds the _Points_ pattern type. Prefer the xref:dressups/array.adoc[Array Dressup] ([.since]#1.1 and later#).

* image:CAM_SimpleCopy.svg[width=32] xref:modify/simple-copy.adoc[Simple Copy]: Creates a non-parametric copy of one or more selected Operations ([.since]#26.3 and later#: multiple selection).

=== Miscellaneous

* image:CAM_Area.svg[width=32] xref:misc/area.adoc[Area]: Creates a feature area from the selected objects.

* image:CAM_Area_Workplane.svg[width=32] xref:misc/area-workplane.adoc[Area Workplane]: Selects a workplane for a feature area.

Both Area commands appear on the _Helpful Tools_ toolbar only when xref:reference/experimental.adoc[experimental features] are enabled.

* xref:misc/property-bag.adoc[Property Bag]: Creates an object that stores custom reference properties which Operations and Tool Bits can use through expressions. Found in menu:CAM[Utils].

* xref:inspect/set-start-point.adoc[Start Point Selection]: Sets the Start Point of the selected Operation from a picked vertex; available from the Operation's context menu and, [.since]#26.3 and later#, from the Profile and Pocket Shape task panels.

* image:CAM_Compound.svg[width=32] Compound: Creates a compound Toolpath object from selected Toolpaths (scripting and macro use; not in toolbars).

=== Context menu

Right-clicking in the model tree offers context-dependent commands (improved in [.since]#26.3 and later#):

* On shapes: xref:job/job.adoc[New Job].
* On a Job: xref:inspect/op-active-toggle.adoc[Toggle Operation], xref:job/export-template.adoc[Export Template], xref:job/sanity-check.adoc[Sanity Check] and xref:output/post-process.adoc[Post Process].
* On Operations: the Path Dressup submenu (single Operation), a Path Modification submenu with Array, Copy Operation and Simple Copy, Toggle Operation, xref:inspect/inspect.adoc[Inspect Toolpath] (single Operation), Post Process and xref:output/post-process-selected.adoc[Post Process Selected].
* On an Operation that has a Start Point: xref:inspect/set-start-point.adoc[Start Point Selection].
* On a Tool Bit: Save Toolbit and Save Toolbit As.

=== Obsolete Commands

* image:CAM_Datums.svg[width=32] xref:job/fixture.adoc[Fixture]: Inserted a fixture-offset (G54 to G59) command. Removed from menus in [.since]#1.1 and later#; Fixtures are now set in the Job's Output settings.

* image:CAM_Face.svg[width=32] xref:operations/mill-face.adoc[Face]: Legacy facing operation. Replaced by xref:operations/mill-facing.adoc[Mill Facing] in [.since]#26.3 and later#; existing documents still open.

* image:CAM_Tapping.svg[width=32] xref:operations/tapping.adoc[Tapping]: Experimental G84/G74 tapping operation in [.since]#introduced in 1.1#. Consolidated into xref:operations/drilling.adoc[Drilling] as the _Tapping_ Strategy in [.since]#26.3 and later#.
